# notes/ — 층 2. 수집된 내용의 파악과 정리

둘째 층이다. [sources/](../sources/README.md) 에 모은 원전을 **읽고 파악한 것을 자연어로 적는다.**
DB([db/](../db/README.md))에 넣기 전 단계이고, DB 에 들어가지 않는 것(읽으며 안 것, 판단, 아직 못 정한 것)이
남는 곳이다.

## 왜 따로 두는가

DB 는 구조화한 결과다 — 항목·관계·id 로 적을 수 있는 것만 들어간다. 그런데 원전을 읽어 아는 것의
상당수는 그 틀에 들어가지 않는다. "이 원전은 어떻게 구성되어 있고 어디까지 믿을 만한가",
"이 두 원전이 같은 이야기를 어떻게 다르게 하는가", "아직 읽지 않은 부분은 어디인가" 같은 것이다.
지금까지는 그런 것이 README 와 TOML 주석, 항목의 `note` 에 흩어져 있었다. 여기 모은다.

## 무엇을 적는가

- **원전별 파악** — 각 원전이 무엇이고, 어떻게 구성되어 있고, 위치를 어떻게 적고, 이 저장소가 어디까지
  읽고 대조했는가. [원전별-파악.md](원전별-파악.md).
- **주제별 정리** — 한 이야기를 원전 여럿이 어떻게 전하는지 모아 읽은 것. 어느 원전을 따를지,
  무엇을 이설(`variants`)로 둘지의 판단 근거. 파일 하나에 주제 하나(예: `페르세우스-원전-대조.md`).
- **대조 기록** — 항목의 인용 위치를 원문에서 확인한 작업의 기록. 어느 원전을 전건 확인했고 무엇이 남았는가.

## 규칙

1. **자연어로 쓴다.** 표·목록은 좋지만 스키마는 없다. 형식 때문에 적지 못하는 것이 없어야 한다.
2. **원전 위치를 적는다.** 무엇을 읽고 안 것인지 — `apollodorus.library 2.4.2` 처럼 DB 와 같은 표기로.
3. **DB 에 들어간 것은 id 로 가리킨다.** 정리한 결과가 항목이 되었으면 `event medusa-slain` 처럼 적어 두 층을 잇는다.
4. **여기 적은 것은 DB 가 아니다.** 산출물은 여기를 읽지 않는다. 산출물에 나와야 하는 것은 DB 로 옮긴다.
5. 날짜를 적는다. 읽은 것은 쌓이고, 나중의 판단이 앞의 것을 뒤집을 수 있다.
